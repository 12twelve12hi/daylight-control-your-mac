# Handoff: Mirror v2, the Wi-Fi mirror transport (LOOSE_ENDS A9)

Status: built and green in CI; unverified on the DC-1. Domain: Daylight Ink (android/), `mac/Daylight/Sources/Mirror/` (except the adb client and server policy files), the Kit `Mirror/` parsers, PROTOCOL section 14, the SPEC rows listed below, and their tests.

Writing rules: no em-dashes; LivePaper is a transflective LCD; the backlight is DC dimming; VRR is 45 to 90 Hz.

## 1. What was built

A second mirror transport that needs no USB debugging and no cable. Settings > Mirror > "Transport": "USB (adb)" (unchanged) or "Wi-Fi (Daylight Ink screen stream)".

- Protocol (docs/PROTOCOL.md section 14, commit a3d0a21, wording fix b90c421): MIRROR_HELLO 0x0080 (64-byte device name, codec id BE), MIRROR_PACKET 0x0081 (the scrcpy 12-byte header BE plus Annex-B, or the 12-byte session packet), MIRROR_STATUS 0x0082 (`<BBHHHII`, states 0 to 8, flags, fps, size, bit rates), MIRROR_CONTROL 0x0071 (`<BBHIHH`, STOP / START / REQUEST_KEY_FRAME / RELEASE with clamped parameters). Ten golden vectors in the manifest's new `mirror_cases` array (`protocol/gen_golden.py`, four copies regenerated by `make golden`); the 26 v1 cases and every v1 test are unchanged. The web client ignores the opcodes (its `decodeServer` returns `{ opcode }` for unknown ones, and the Mac only sends MIRROR_CONTROL to connections that announced themselves with MIRROR_STATUS, which the web page never does).
- DaylightKit (a2ceaa1): `MirrorStream` (codec), `MirrorStreamReceiver` (the PROTOCOL 14.5 rules per connection as a pure state machine: packet before HELLO, malformed packets with a rate-limited key frame request, the 2 s stall rule), `LumaGrid` and `FrameDiffEngage` (engage by frame differencing: a 48x64 luma grid inside the canvas crop, a cell changed at a delta of 24 or more, a frame changed at max(4 cells, 0.2 percent of cells), two changed frames within 0.25 s engage, 1.0 s quiet releases; one changed frame, such as a status bar clock tick, never engages). Settings `mirrorTransport`, `mirrorStreamMaxSize` 1600, `mirrorStreamBitRate` 7,000,000, `mirrorStreamMaxFps` 30, `mirrorStreamKeyIntervalMs` 2000, `mirrorDiffThreshold` 0.002. FailureText rows 34 to 38 (SPEC 13.3). SPEC 8 (fourth row), 9.4b (consent flow), 11 (keys), 13.3, 16 F8 to F10.
- Daylight Ink (4596bad, 4afa371): `protocol/MirrorFraming.kt`; pure, JVM-tested `mirror/{MirrorSession,MirrorBackpressure,MirrorStats,EncoderSizing}.kt`; Android glue `mirror/{ScreenEncoder,MirrorController,ScreenStreamService,ConsentActivity,MirrorIcons}.kt`. Foreground service of type mediaProjection with a persistent notification ("Sharing screen with your Mac", Stop), consent through `createScreenCaptureIntent()`, MediaCodec H.264 with a surface input (long side at most 1600, multiples of 16, 30 fps cap, 7 Mbit/s default, key frame interval from the Mac, repeat previous frame after 250 ms), rotation restarts the encoder with a new HELLO, thermal SEVERE halves the frame rate, the 1 MiB / 256 KiB backpressure rule on OkHttp's queue keeps ink, pills and PING flowing. The stream shares the app's one WebSocket (the service holds it with role `overlay`, same clientId). Settings > "Share this screen with the Mac over Wi-Fi (no cable, no USB debugging)" with "Share screen with your Mac" and "Stop sharing". Pills untouched.
- Mac app (f9c0102, 54b5088, edc0009): `Mirror/WifiMirrorSource.swift` conforms to the frozen `MirrorFrameSource` contract (no contract change): one receiver per connection, its own `H264Decoder`, the USB source's crop slot reused so crops and orientation match exactly, START only to announced connections (roles ink, overlay, test; never to state 8), newest HELLO wins, STOP when leaving mirror or the Wi-Fi transport, RELEASE on quit, the stall timer, rows 34 to 38, diagnostics `mirror.wifi.*` (bitrate, fps, decodeLatencyMs, engageSource, streamSize, tabletState, connections, streamer). `MirrorController` switches transports, keeps the USB pen watcher running in Wi-Fi mode so `getevent` stays the preferred engage signal when the tablet is also on USB. `AppDelegate` and the self-test peel mirror opcodes off `server.onInkMessage` on ink.queue before the router (no change in Server/ or Ink/). `Mirror/WifiMirrorSelfTest.swift` encodes a solid-colour key frame with VideoToolbox for the self-test probe.

## 3. UNVERIFIED items and their fallbacks

Tablet side (every other Android API name came from developer.android.com pages fetched during the work):

1. Whether the DC-1 encoder honours `KEY_REPEAT_PREVIOUS_FRAME_AFTER` and `KEY_MAX_FPS_TO_ENCODER` (D21). Fallback: if it does not, a still page triggers the Mac's 2 s stall rule (row 36) and a key frame request, which recovers on its own; the fix is a periodic sync-frame request in `ScreenEncoder`.
2. `Display.getRealMetrics` (deprecated) inside `runCatching`, falling back to `resources.displayMetrics`.
3. `registerReceiver` without export flags for the battery saver broadcast (allowed at targetSdk 33) inside `runCatching`.
4. The direct consent launch through the "display over other apps" background-start exception inside `runCatching`; the "Tap to allow" notification is posted either way (D22).
5. `MediaProjectionConfig.createConfigForDefaultDisplay()` on API 34 and later inside `runCatching`, falling back to the plain intent (the DC-1 runs Android 13).
6. `CodecException` details are not read; only the exception text is logged; one automatic encoder restart, then ENCODER_UNAVAILABLE (row 35).
7. SolOS wording of the consent prompt and whether locking the screen ends the projection (D19).

Mac side: none. The VideoToolbox encode calls of the self-test were checked against developer.apple.com; a failed encode prints a SKIP line, never a pass.

## 4. Battery and thermal notes

Default 7 Mbit/s, 30 fps, 1200 x 1600 on the DC-1. A still page costs about four tiny repeat frames a second. STOP from the Mac stops the encoder and detaches the virtual display's surface (PAUSED); only the held projection and its notification remain, and the next START needs no new consent. RELEASE or the notification's Stop ends it all. At thermal status SEVERE or above the frame rate cap halves through an encoder restart and MIRROR_STATUS flag bit1 is set; battery saver is reported (bit2) without changing the encoder. Nothing charges the tablet in this transport; the COMPARE 2.1 battery figure is an estimate until D23 is measured.

## 5. Decisions recorded

- The mirror family lives in a separate golden array `mirror_cases` so v1 tests (which assert 26 cases) stay unchanged; manifest `version` stays 1.
- The announce MIRROR_STATUS after every HANDSHAKE_ACK 0 carries the current state (IDLE, PAUSED after a Wi-Fi drop with a held projection, or UNSUPPORTED); PROTOCOL 14.3 says so.
- "Share" in the app takes consent and waits in PAUSED; the Mac's START streams at once.
- The waiting-for-consent state shows in the Mac's mirror status and Diagnostics (`connecting <label>, waiting for consent on the tablet`, `mirror.wifi.tabletState`), like the USB "connecting <serial>" status; it is not a failure, so it has no FailureText row.
- Commit trailers name the session that wrote the commits.
