# Reusable code from other projects

What open-source code Daylight Whiteboard Camera could adopt, port or learn from. This page comes from the research swarm of 2026-10-04: 45 target reports, each checked by a verification agent who opened the cited repository files (cloned at the default branch on that date) and dropped anything the code did not show. Companion pages: `IDEAS-FROM-OTHER-PROJECTS.md` (the ideas, ranked) and `ANTI-PATTERNS.md` (what to avoid).

Writing rules: no em-dashes; LivePaper is a transflective LCD; the backlight is DC dimming; VRR is 45 to 90 Hz.

## How to read this page

Daylight is Apache-2.0 (`LICENSE`). Code under MIT, BSD, Apache-2.0 or the Unlicense can be copied or ported with its notice added to `THIRD_PARTY_NOTICES.md`. Code under GPL, AGPL, MPL or a commercial license cannot be copied into Daylight; for those the column says "reimplement from the idea", which means reading the design, closing the file, and writing our own code from the description in this page. Every row was checked against the license file in the cloned repository.

"Replaces or adds" names the Daylight file the verifier found by searching the tree. Risk covers license, maintenance, and platform.

## 4. What not to adopt, and why

| Candidate | Reason |
|---|---|
| A UDP or WebRTC data channel for live points | Daylight already sets TCP no-delay on both ends and batches per frame; the verifiers found no measured stall to fix. First add an ink-stall metric (max and p99 gap between `STROKE_CHUNK` arrivals) to Diagnostics ([moonlight-common-c](https://github.com/moonlight-stream/moonlight-common-c/blob/master/src/InputStream.c) shows the cost of a custom UDP path) |
| WebTransport or WebCodecs in the web page | Both are `[SecureContext]` ([webcodecs](https://github.com/w3c/webcodecs), [Pointer Events](https://w3c.github.io/pointerevents/#pointerevent-interface)); the plain `http://` LAN page cannot use them. Only the USB `localhost` path could |
| goMarkableStream's zstd delta frames instead of H.264 | High risk: Go with ARM assembly and a new Mac decoder, for a bandwidth gain the Wi-Fi mirror does not need ([delta.go](https://github.com/owulveryck/goMarkableStream/blob/main/internal/delta/delta.go)) |
| The full Microsoft ISF format | About 9,200 lines of Huffman, LZ and transform tables ([dotnet/wpf](https://github.com/dotnet/wpf/tree/main/src/Microsoft.DotNet.Wpf/src/PresentationCore/MS/internal/Ink/InkSerializedFormat)); gzip and, if needed, varint deltas get most of the gain |
| androidx.ink / google/ink on the Mac | [google/ink](https://github.com/google/ink) is Apache-2.0 but Android only; the Mac re-renders from raw points, so using it on the tablet alone could make wet ink and the camera picture diverge |
